# Godot project (game)

Godot 4 .NET project `RoadmanSimulator` (Forward+ renderer, Jolt physics), scripted in C#. See `docs/architecture.md` and ADR 0001.

## Layout

- `Roadman.Core/`: engine-free C# logic (road graph, routing, wanted level, missions, death and respawn, saves and settings in `Saves/` and `Settings/`). No Godot references. Tests in `Roadman.Core.Tests/` (xUnit).
- `scenes/`, `scripts/`: Godot scenes and node scripts. `scripts/autoload/` holds `Events` (signal bus) and `GameState` (owns `PlayerState`).
- `tests/`: engine-dependent tests (gdUnit4Net). Built in `Debug` only; export builds contain no test code.
- `addons/`: gdUnit4, and Terrain3D if ADR 0004 chooses it.
- `maps/<map-id>/`: generated map packs. Never edit them by hand; they are git-ignored.

## Conventions

- All projects target `net10.0` (ADR 0007); `global.json` pins the SDK.
- Nullable reference types are on in every project.
- Test packages (gdUnit4Net, `Microsoft.NET.Test.Sdk`) are referenced only in `Debug`. `Directory.Build.targets` keeps the game assembly a library.
- Declare Godot signals with `[Signal]` delegates.
- Logic that doesn't need the engine goes in `Roadman.Core`, with tests.
- Keep scenes small, and prefer building node trees in code. Hand-merged `.tscn` edits break easily.
- Use `[Export]` on anything that will be tuned.
- Autoloads (`Events`, `GameState`) stay small.
- Keep `.import` files in Git.
- Missions refer to marker ids, never to raw coordinates.
- Debug keys: new debug actions use letter or symbol keys (physical keycodes), never F-keys (on macOS they need Fn, and F3 is Mission Control). The existing F2 (`debug_orthophoto`) stays.

## Commands

Run these from the repo root.

```sh
dotnet build game/RoadmanSimulator.sln                       # all projects, Debug
dotnet test game/Roadman.Core.Tests                          # Roadman.Core unit tests (xUnit)
godot --headless --path game --import                        # needs a wrapper, not a symlink; see "Godot binary" in the root CLAUDE.md
GODOT_BIN=/Applications/Godot_mono.app/Contents/MacOS/Godot \
  dotnet test game/RoadmanSimulator.csproj --settings game/.runsettings  # gdUnit4 tests in tests/; run the import first
dotnet format game/RoadmanSimulator.sln --verify-no-changes  # format check
godot --headless --path game --quit-after 120 -- --new-game  # the main scene (Main.tscn) starts a game at once; /verify's "headless startup" step
dotnet build game/RoadmanSimulator.csproj -c ExportRelease   # release assembly, no test code; output in game/.godot/mono/temp/bin/ExportRelease/
godot --path game --resolution 1600x900 -- --screenshot overview build/screenshots/overview.png --map somero  # screenshot of a camera preset; windowed, see "Screenshots"
godot --path game --resolution 1600x900 -- --screenshot centre-street-level build/screenshots/centre-street-level-player.png --map somero --player --seed 1  # the player in the third-person view
```

`GODOT_BIN` must point at the real Godot .NET binary, not a symlink. The gdUnit4 adapter writes its runner scene to `game/gdunit4_testadapter_v*/` on each run (git-ignored).
Building with `-c ExportRelease` or `ExportDebug` re-restores the shared `obj/` without test packages; the next Debug `dotnet build` or `dotnet test` restores them again, so don't pass `--no-restore` after switching configuration.

## Map loading

- `World` adds a `MapLoader` (`scripts/world/MapLoader.cs`), which reads `res://maps/<id>/manifest.json` and instances every tile under `MapLoader/Tiles`. The id comes from `MapLoader.MapId` (`World.MapId` sets it, which `Main` uses for a save's map) or the project setting `roadman/map/id` (default `somero`). Errors name the pack path and say to run `/regen-map <id>`.
- Terrain collision bodies are in the group `map_terrain`. Use `MapLoader.TerrainHeightAt(x, z)` for ground heights; never hard-code them (Somero's terrain is about 81 to 138 m). New collision bodies are queryable only after a physics frame: await `MapLoader.WaitForTerrainCollisionAsync()` first.
- Map materials: `MapLoader` sets `TerrainMaterial` on each tile's `terrain` mesh and `BuildingMaterial` on every `bld_` mesh. Both default to the placeholders in `materials/placeholder/` (`terrain.tres`; `building.tres` with `building.gdshader`, which colours up-facing faces as roof). Replace that folder, or set the two exports, when the art-direction palette exists. Lighting (sun energy and shadow distance, ambient energy, AgX tone mapping, exposure) is exported on `World`. In a game started by `Main`, `World.QualitySettings` sets the sun's shadows, splits and distance (see "Menus, settings and saves").
- Roads (ADR 0012): tiles hold `road`, `path` and `bridge_osm_way_<id>[_p<n>]` meshes (imported from `-col` nodes, so each has a `StaticBody3D`). Their bodies are in the group `map_roads`, so `TerrainHeightAt` still returns bare terrain, 0.05 m (Somero's `surface_offset_m`) under the road surface. `MapLoader` sets `RoadMaterial` on `road` and bridge meshes and `PathMaterial` on `path` (placeholders `materials/placeholder/road.tres` and `path.tres`).
- `MapLoader.RoadGraph` (`Roadman.Core.Maps.RoadGraph`) is read from `road_graph.json` after the tiles, before `MapLoaded`. A missing or invalid file pushes an error with the `/regen-map` hint and leaves it null; the tiles still load. Routing comes with the traffic AI spec.
- Place data (ADR 0013): after the road graph, `MapLoader.Places` (`Roadman.Core.Maps.PlaceIndex`) is built from `buildings.json` and `pois.json`. A missing or invalid file (or links that don't agree, or a `pois.json` whose `area` isn't the manifest's) pushes an error naming the path and `/regen-map <id>` and leaves it null; the tiles and road graph still load.
- Building collision bodies (glTF `bld_<id>_c<k>-colonly`, one per footprint part, k = 0, 1, ...; ADR 0006) are the `StaticBody3D` children of a tile and are in the group `map_buildings`. No collision node name equals a visual mesh name once the suffix is stripped, so the importer keeps each body's name and only drops the suffix (`bld_<id>_c<k>`). `MapLoader` resolves each body from its own name alone, re-appends `-colonly` and renames the body to that glTF node name; node order is never used. `Roadman.Core.Maps.BuildingBodies` holds that rule and checks, per tile, that the bodies and the `collision_nodes` of the buildings whose `tile` is that tile are a bijection; a mismatch (a body Godot renamed to `@StaticBody3D@…`, a name not in `buildings.json`, a missing or duplicate body, a body of another tile) pushes an error naming the tile, the first offending names and `/regen-map <id>`, and keeps the unresolved, extra and duplicate bodies out of `map_buildings`, so the inspector never shows a wrong building. `MapLoader.BuildingBodyCount` is the number resolved. `MapLoader.BuildingOf(body)` / `BuildingIdOf(body)` resolve a body through `PlaceIndex.TryGetBuildingByNode`.
- World edge (ADR 0015): tiles the boundary passes through also hold `edge_cliff` (imported from `edge_cliff-col`: ledge, face, seams and skirt; a mesh with a `StaticBody3D` child; `MapLoader` puts the body in the group `map_edge`, `MapLoader.EdgeGroup`, not in `map_terrain`, so `TerrainHeightAt` still returns bare terrain; `MapLoader.GroundOrEdgeHitAt(x, z)` returns the highest hit on either), and every tile holds `edge_bottom` (the bottom cap under the slab, visual only). Both use the plain glTF material `edge_cliff`, which `MapLoader` doesn't override yet. After the places, `MapLoader.Boundary` (`Roadman.Core.Maps.Boundary`) is read from `boundary.json` by `BoundaryReader` (`MapLoader.BoundaryPath`); a missing or invalid file pushes an error naming the path and `/regen-map <id>` and leaves it null, and the tiles, road graph and places still load. The player spawns from its `spawn_area`; the barriers and the void trigger are placed from it (see "World edge"). The `world-edge` screenshot preset has absolute heights, because its camera is outside the build area.
- `[importer_defaults]` in `project.godot` sets every scene import to name suffixes on, mesh compression off, LODs off, shadow meshes on and static light baking. A hand-made `.glb` added later gets these too; correct its import settings and commit its `.import` file.

## Player

Spec: `docs/specs/player-on-foot.md`; ADR 0016.

- `scripts/player/Player.cs` (`Roadman.OnFoot.Player`), a `CharacterBody3D` built in code: capsule, placeholder model (`materials/placeholder/player.tres`), origin at the feet. Movement maths in `Roadman.Core.Player.OnFootMotion` (the exports are copied into `Motion` each physics frame); project default gravity; jump only on the floor (`JumpSpeed` = `OnFootMotion.JumpVelocity(JumpHeight, Gravity)`). It writes its global position to `GameState.Instance.Player.SetPosition` after `PlaceAt` and every physics frame. `InputEnabled` false gives no move, run, run-toggle or jump input (it still falls); `RunToggle` keeps its state.
- Controls (every event `device` −1, any pad; keys by physical keycode):
  - `move_forward`/`move_back`/`move_left`/`move_right`: W/S/A/D, and the left stick (axis 1 `LeftY` −/+, axis 0 `LeftX` −/+). Read with `Input.GetVector` (radial deadzone 0.2, the actions' `deadzone`).
  - `run`: Shift, held; keyboard only.
  - `run_toggle`: the left-stick click (`GamepadButtons.LeftStickClick`, button 7); gamepad only. `Roadman.Core.Player.RunToggle` (`Player.RunToggle`): a press flips it; while it is on, the move vector going from non-zero to zero (the stick back inside its deadzone) turns it off, so the next movement walks; a press while standing still stays on until movement starts and stops. Shift never changes it. Window focus loss calls `ResetMovement()`, so the toggle stays as it was. Running = `run` held or the toggle on.
  - `jump`: Space, and the south face button (`GamepadButtons.South`, button 0; Godot's enum name for it is `JoyButton.A`, used only through that constant). Name gamepad inputs generically everywhere (ADR 0016).
  - `camera_left`/`camera_right`/`camera_up`/`camera_down`: the right stick (axis 2 `RightX` −/+, axis 3 `RightY` −/+); mouse motion orbits too (not an action).
  - `pause`: Esc and the gamepad Start button (`GamepadButtons.Start`, button 6; "Start button" in text). Handled by `Main` (see "Menus, settings and saves"); in the game it replaces `ui_cancel`, so the east face button (`GamepadButtons.East`) is free for gameplay.
  - Half tilt (spec criterion 17) is the raw stick value halfway between the deadzone and full tilt: 0.6 with the 0.2 deadzone, which `Input.GetVector` remaps to 0.5, so half the speed.
- Collision layers (`scripts/world/CollisionLayers.cs`): map bodies on layer 1 (`CollisionLayers.Map`), the player on layer 2 with mask `CollisionLayers.PlayerMask` (map and both barrier layers, `CollisionLayers.Barriers`), loose barrier pieces on layer 3 (`CollisionLayers.Barrier`), layer 4 (`CollisionLayers.Vehicle`) reserved for vehicles, unbroken barrier items on layer 5 (`CollisionLayers.BarrierStatic`, which the void trigger doesn't monitor; ADR 0017). Map rays (`MapLoader`, `StreetLabelHud`, `PlaceInspector`) and the camera's spring arm use mask 1, so they never hit the player or a barrier. The spawn ray and capsule query look at every layer, excluding the player.
- `scripts/player/PlayerCamera.cs`: pivot at `PivotHeight` above the feet (`FollowSmoothing` is a time constant in seconds, 0 = rigid), `SpringArm3D` with a sphere of `CameraCollisionRadius` (shortens at once, extends back at `ArmReturnSpeed`), `Camera3D` (`Fov` 70). Mouse orbit while captured (`MouseSensitivity`), and right-stick orbit each physics frame while it is current and `InputEnabled` (`OrbitStick(stick, delta)`, `StickSensitivity` rad/s at full tilt; stick up pitches up), pitch clamped to `MinPitchDegrees`..`MaxPitchDegrees`, not inverted; `InvertMouseY`/`InvertStickY` exports for the settings view. No automatic swing-back; only the first spawn puts it behind the player (`PlaceBehind`, `StartPitchDegrees`). The mouse is captured while it is current and the window has focus; it doesn't handle `ui_cancel` (ADR 0018): the pause menu releases it (`ReleaseForPause()`, `WantsCapture` stays) and Resume captures it again (`ResumeCapture()`, only when it wanted the capture, is current, has input and the window has focus; never while the tree is paused); a left click captures it again. In a game started by `Main`, `ApplySettings(GameplaySettings)` sets the inverts and the sensitivities (`DefaultMouseSensitivity` 0.003 / `DefaultStickSensitivity` 3 × the multiplier) at every spawn, load and respawn (`World.CameraSettings`; null in direct `World` runs, which keep the exports). Headless tests check `WantsCapture`. Running `World.tscn` directly (the editor, tests), Esc does nothing: there is no pause menu without `Main`; switch windows or use the debug camera to free the mouse. The headless display server can't capture the mouse (`Input.MouseMode` stays visible, although the window reports focus), so tests call `Orbit()` and can't check a capture being restored.
- Spawn (`World`): after `MapLoader.WaitForTerrainCollisionAsync()`, up to `SpawnMaxAttempts` draws from a `SpawnPicker` over `Boundary.SpawnArea`. A draw passes when a downward ray's first hit is `map_terrain` and the capsule `SpawnDropHeight` above it overlaps nothing but terrain. Then `PlayerSpawned(position)`, the player camera becomes current and `StreetLabelHud.Target` is the player. A null `Boundary`, no terrain collision within `SpawnPhysicsWaitFrames`, open ground `SpawnPicker` can't draw from, or no passing draw pushes an error naming `res://maps/<id>/boundary.json`, the actual reason (`World.LastSpawnFailure`) and `/regen-map <id>`; there is no player, and in debug builds the debug camera stays current (a release build has no camera then: a plain default view). A map reload frees the player and spawns again. `SpawnDropHeight` and `SpawnMaxAttempts` are exports on `World`, because they are needed before a player exists.
- Seed: `--seed <n>` on the user command line (`Roadman.Core.Tools.SeedArg`; `ScreenshotArgs` accepts it too), else the time; `World.Seed` overrides both in tests. `Main` parses `--seed` from its own user args (`Main.UserArgs` or the command line) and sets `World.Seed` on every `World` it creates (the time when absent), so a new game, and a load that needs the spawn draw, draw as a direct `World` run with that seed. The spawn prints `Player: spawned at (x, y, z), seed <n>, draw <k>`.
- Death and respawn: see "World edge". The player's `GravityOverride` (a `Vector3?`), while set, replaces gravity and skips movement, floor and jump logic (the void fall).
- Debug builds: `scripts/debug/DebugBuild.cs` (`DebugBuild.IsDebug`) is the only code that calls `OS.IsDebugBuild()` (ADR 0016); every debug-only decision asks it, and nothing else may call `OS.IsDebugBuild()`. Tests set `DebugBuild.Override` (tests only; reset it to null afterwards) to build the release layout. `World` adds the `DebugCamera` only in debug builds (`World.Camera` is null in release, where only the player camera exists).
- Debug camera toggle: `debug_camera` (`World.DebugCameraAction`), bound to two physical keycodes, `Key.Quoteleft` (96) and `Key.Section` (167), no gamepad. From Godot's key mapping: the key left of 1 on Windows (scancode 0x29) and on US Macs (`kVK_ANSI_Grave`) is `Quoteleft`; on ISO Macs such as the Finnish layout (`kVK_ISO_Section`, §) it is `Section`. On ISO Macs `Quoteleft` is the `<>` key beside left Shift, so that key toggles too; acceptable for a debug-only key. To be confirmed in the playtest. `World.ToggleDebugCamera()` (returns false when it did nothing: no debug camera, no player, a screenshot run) puts the debug camera at the player camera's global transform and `Fov` and makes it current, and sets `InputEnabled` false on the player and the player camera; back, it enables both and calls `PlayerCamera.Activate(captureMouse:)` with whether the player camera held the mouse before. `World.DebugCameraActive` says which is on; every spawn starts on the player camera. Without a player it does nothing and the debug camera stays current.
- `DebugCamera` ignores its input while it isn't current.
- Screenshot runs: the player spawns (seeded by `--seed`) but is hidden, its camera is never made current and `StreetLabelHud.Target` stays null, so preset images are unchanged; only `--player` shows it (see "Screenshots").


## World edge

Spec: `docs/specs/world-edge-game.md`; ADR 0017. Code in `scripts/world/edge/`, `scripts/hud/DeathScreen.cs` and `Roadman.Core/Edge/`.

- `MapLoader/Edge` always exists. With a `Boundary`, `MapLoader` creates `MapLoader.EdgeGeometry` (`Roadman.Core.Edge.EdgeGeometry`), `Edge/VoidTrigger` (before `MapLoaded`) and `Edge/Barriers`, which builds the items once the terrain collision is queryable (roadblock stands use `GroundOrRoadHitAt`; `EdgePhysicsWaitFrames`, else an error naming `boundary.json` and `/regen-map <id>`). The stands stand on the ring, where the terrain, road and path meshes end (their border vertices lie on it to float rounding), so a ray right under a stand can miss: `BarrierLayout.StandGround` then takes the ground `RoadblockStandGroundInset` (0.05 m) inward of it; WorldEdgeTest's criterion 8 check uses the same rule. Await `MapLoader.WaitForWorldEdgeAsync()` before using them. A null `Boundary` gives none of them. A reload frees and rebuilds them.
- Barriers: one item per roadblock and fence, a `Roadblock`, `LandFence` or `WaterFence` (`BarrierItem`, a `StaticBody3D`), named `id.ValidateNodeName()` (`ItemId` holds the real id), on `CollisionLayers.BarrierStatic` with mask 0, with one `ConvexPolygonShape3D` per collision box of `BarrierLayout`. No visual children: the pieces are instances in one `MultiMeshInstance3D` per type and piece kind under `Barriers/Batches` (`<Kind>_<Piece>`). The tuned values are in a `BarrierSettings` resource (`scripts/world/edge/BarrierSettings.cs`, `[GlobalClass]`), in inspector groups per type with the group as the property prefix: `Roadblock` (`RoadblockHeight` 0.9, `RoadblockStandSpacing`, ...), `Land Fence` (`LandFenceHeight` 0.9, `LandFencePostSpacing` 2.5, whose post values water fences use too), `Water Fence`, and `Collision` (`CollisionThickness`, `CollisionDepthBelow`, `JointOverlap`). `MapLoader.BarrierSettings` (export) holds it and every `Barriers` it creates gets it as `Barriers.Settings`, so a change lasts across reloads and takes effect at the next load. A value out of range (`BarrierParameters`) pushes an error and builds no barriers. The three type classes have no exports. Materials: `materials/placeholder/barrier_*.tres` and `fence_*.tres`.
- Rules (checked by the xUnit tests): no piece more than 0.9 m above its base, nothing more than 1.0 m outward, collision covering the ring with no gap over 0.1 m, one post per fence joint.
- Breaking: only vehicles. A breaker is a `PhysicsBody3D` implementing `IBarrierBreaker` (`BreakerVelocity`) in the group `Barriers.BreakerGroup` (`barrier_breakers`); the player is never one. `Barriers._PhysicsProcess` (before the physics step; returns at once when the group is empty) runs `BreakTouchedItems(delta)`: each breaker at `BarrierSettings.BreakingSpeed` (3 m/s) or faster sweeps its enabled `CollisionShape3D`s along velocity × delta (`SweepBreaker`: `IntersectShape` at the start, at the `CastMotion` hit and at the end, mask `CollisionLayers.BarrierStatic`, margin `BreakingSweepMargin` 0.04 m), and every item touched breaks with `Break(id, velocity)`: `MarkBroken(id)` (body out of the tree, instances hidden), then one `RigidBody3D` per layout piece under `Barriers/LoosePieces` (`<item node name>_<i>`, the batch mesh in an orthonormal frame on the piece's box, a box, cylinder (posts) or sphere (round floats) shape, layer `Barrier`, mask `Barriers.LoosePieceMask` (map, both barrier layers, player, vehicle), mass `BreakParameters.PieceMass` from `BreakingPieceDensity` 300 kg/m³ and `BreakingMinPieceMass` 0.5 kg, the breaker's velocity), then the `ItemBroken(itemId, pieceCount)` signal; `LoosePiecesOf(id)` and `LoosePieceCount` count only live pieces (valid, not queued for deletion). The `Breaking` settings are checked each pass (`BreakParameters`, in `Roadman.Core.Edge`); a bad value pushes one error and nothing breaks. `RestoreAll()` rebuilds every broken item and frees `Barriers/LoosePieces`. `World` calls `RestoreAll()` on every death respawn; a reload rebuilds everything.
- Void trigger (`VoidTrigger`, an `Area3D`): one `ConvexPolygonShape3D` per prism (`Prism<i>`), mask `VoidTrigger.MonitoredLayers` (player, loose pieces on `Barrier`, vehicle; not the map, not `BarrierStatic`). It emits `BodyEnteredVoid(body, outward)`; `World.HandleVoidEntry` routes it: the player (state `Alive`) starts the death sequence, an `IVoidFaller` gets `EnterVoid(outward)` once, another `RigidBody3D` falls in `World/VoidFall` (gravity scale 0, the `VoidPull` force) and is freed below `void_trigger.bottom_y`, below the safety net or after `MaxFallTime`; other bodies are ignored. Jolt reports a `CharacterBody3D` to the area a frame late, so `World` also tests the player itself each physics frame (the centres of the capsule's end spheres moved one radius outward, against `EdgeGeometry.IsInVoid`); whichever sees the entry first starts the sequence. The trigger path for the player starts it from the area's `body_entered` callback without errors (tested), so it isn't deferred.
- Safety net: each physics frame `World` checks the player and the bodies registered with `World.TrackVoidBody`. A body is dropped (`UntrackVoidBody`, which disconnects its `TreeExiting` handler) when it leaves the tree for any reason, freed or only removed for reparenting, and isn't tracked again on re-entering until `TrackVoidBody` is called again; `World` connects each new `Barriers.ItemBroken` and tracks that item's loose pieces (already under `LoosePieces`); a map load drops all. Checked against `EdgeGeometry.IsBelowSafetyNet(y, SafetyNetMargin)`; one below it that isn't falling is a void entry with `OutwardAt` at its x/z, except that a plain `RigidBody3D` is freed at once.
- Death sequence (`World.Death`, a `Roadman.Core.Edge.DeathSequence`, advanced in `World._PhysicsProcess`):
  - Falling (`FallTime` 3 s): `Die()` after the losses are recorded; player and player camera input off; the player's collision mask 0 (layer kept); `Player.GravityOverride` = `VoidPull` (`VoidOutwardAcceleration` 4, `VoidDownAcceleration` the project gravity `physics/3d/default_gravity` until set); `World.DeathCamera` starts at the player camera's transform and `Fov` and moves (smoothstep over `PullBackTime`, in `_Process`; `Advance(dt)` and `TransformAt(t)` for tests) to the nearest ring point at `EdgeGeometry.LedgeHeightAt(s)` + outward × `PullBackDistance` + `PullBackHeight` up, looking at the ring point `LookAtDrop` below the ledge. The mouse is released while the player camera isn't current, as with the debug camera.
  - DeathScreen (`ScreenTime` 5 s): `World.DeathScreen` fades in (`FadeTime` 0.5) with `DeathScreenText.Format(losses)`; the player is hidden and its physics stopped; the street label is `Suppressed` until the respawn. Dismiss: `World._Input` skips the `pause` action (Esc, Start: they open the pause menu instead, ADR 0018) and passes any other key press (not echo), gamepad button press or mouse button press (`World.IsDismissPress`; never the mouse wheel, mouse motion or joypad motion, so not the analog triggers) to `DeathSequence.Dismiss()`, which moves to `Respawning` once `TimeInState` ≥ `MinScreenTime` (2 s) and marks the event handled; an earlier press is ignored, not kept. The respawn then runs in the next `_PhysicsProcess`, as after `Advance`.
  - Respawning: handled in `World._PhysicsProcess` after `Advance` returns (not in the `StateChanged` handler, so every subscriber hears `DeathScreen→Respawning` before `Respawning→Alive`): `Barriers.RestoreAll()`, the spawn draw (same seeded `Random`, so `--seed` repeats it), the player back with zero velocity, gravity, mask and input, camera behind it and current, the screen fading out, `PlayerRespawned(position)`. No passing draw: the spawn error, the player freed, the screen hidden, state `Failed`; debug builds end on the debug camera.
  - The world-edge exports on `World` (`FallTime`, `ScreenTime`, `MinScreenTime`, `MaxFallTime`, `SafetyNetMargin`, `VoidOutwardAcceleration`, `VoidDownAcceleration`) have range hints and are copied into the sequence, the pull and `VoidFall` each physics frame; a value set negative or not finite pushes one error and is set back to its last valid value.
  - `ToggleDebugCamera()` returns false outside `Alive`. A map load or failed load resets the sequence, stops the death camera, hides the screen and clears `VoidFall` and the tracked bodies.
- Sky: `World.SkyShaderPath` (`materials/sky/space_sky.gdshader`), the day sky above the horizon and a procedural starfield below it; the radiance pass (`AT_CUBEMAP_PASS`) draws the old ground colour there, so the lighting doesn't change. `World.SpaceSkyEnabled` (export, read when `_Ready` makes the environment) false gives a plain `ProceduralSkyMaterial` instead.
- `MapLoader.WorldEdgeEnabled` (export, read at each `Load`) false still reads `Boundary` (the spawn needs it) but makes no `EdgeGeometry`, `VoidTrigger` or `Barriers`, so there is no safety net or player void test either.

### Performance check

Spec criterion 27 (under 1 ms per frame on the full pack). `scripts/debug/PerfTool.cs` (`Roadman.Debug.PerfTool`), added by `World` in debug builds when the user args hold `--perf` (`Roadman.Core.Tools.PerfArgs`; exit 1 in a release build): `godot [--headless] --path game -- --perf <spawn|roadblock> <out.json> [--map <id>] [--seed <n>] [--no-world-edge] [--no-space-sky] [--warmup <frames>] [--frames <n>]`. `--no-world-edge` sets `WorldEdgeEnabled` and `SpaceSkyEnabled` false before the map loads, `--no-space-sky` only the sky. `spawn`: the player where it spawned; `roadblock`: on the ground 4 m (`RoadblockInset`) inward of the span midpoint of `roadblock:cut:way/1445392542:0` (from `Boundary`), facing along the span, camera behind. Without that roadblock (a test-area pack) it prints `N/A: not the full pack (...)` and exits 2. Player input off; warm-up (120) then measured frames (600). `Engine.MaxFps` 0 in both modes. Headless runs need `godot --headless --fixed-fps <physics ticks per second>` (one physics step per frame, no sleeping; the tool fails when the measured frames didn't take one step each), so `mean_frame_ms` (real time between frames) is the process and physics work per frame, the headless budget figure. Windowed: vsync off; the budget figure is the main viewport's render time (`RenderingServer.ViewportSetMeasureRenderTime`, `ViewportGetMeasuredRenderTimeCpu` + `...Gpu` each frame: `mean_render_cpu_ms`, `mean_render_gpu_ms`, `mean_render_ms`), with `mean_frame_ms` information only (on the development Mac the GPU time reads 0). The `Performance` `TimeProcess`/`TimePhysicsProcess` monitors are only the peak of the last second, updated about once a second, so they are in the JSON as `peak_process_ms`/`peak_physics_ms` (with `peak_monitor_updates`), information only. The JSON also has `physics_steps`, `headless`, `world_edge`, `space_sky`, barrier item and piece counts and void prism count. `.claude/scripts/perf-world-edge.sh` runs both spots, headless (with `--fixed-fps` from `project.godot`, default 60) and windowed, `PERF_REPEATS` (3) times each, alternating full, `--no-world-edge` and `--no-space-sky` (JSON in `PERF_OUT`, default `build/perf/`), and reports medians: the world edge's cost (full − no-world-edge) and the sky's share (full − no-space-sky). Per spot, headless frame cost + windowed render cost < 1 ms is PASS, else FAIL (exit 1). Not part of `/verify`.


## Menus, settings and saves

Spec: `docs/specs/menu-settings-save.md`; ADR 0018.

- `Roadman.Core/Saves/`: `SaveGame`/`SavePlayer` (`SaveFormat.CurrentVersion` 1), `SaveReader` (strict; `SaveFormatException` with `KeyPath`, `NewerVersion`; `SaveMigrations`, `Default` read-only, tests register steps on their own instance), `SaveWriter`, `SaveSlots` over `ISaveStore` (`MemorySaveStore` in `Roadman.Core.Tests/Saves/`; `SlotId.Autosave`, `SlotId.Manual(1..5)`, `autosave.json`/`slot_<n>.json`, writes `<file>.tmp` then renames), `SaveFactory.Make` (the save-building rules: a manual save needs `canSave`; position and facing only when alive; `"unknown"` / `"dev"` for a blank `generated_at` / version), `PlayTime`, `PlayTimeText`, `SlotText`. `PlayerState.Snapshot/Restore/Reset`. `Roadman.Core/Settings/`: `GameSettings` (groups `Display`, `Audio`, `Gameplay`), forgiving `SettingsReader`, `SettingsWriter`, `WindowSizes`, `VolumeMath` (`ToDb(0)` is −∞: use `IsMuted` for the bus mute), `QualityPreset`, `SettingsFile` (`Load`/`Save` of the file; a missing file gives the defaults), `DisplayRevert` (the 10 s confirm-or-revert state; `NeedsConfirm` for mode, size or render scale), `DisplayChange.Plan` (which window mode and size to send), `WindowSizes.ListFor` (the size list: the fitting sizes plus the current one), `ControlNames` (action labels and generic gamepad and mouse names). `IO/DurableFile.WriteAllText` flushes to disk; `FileSaveStore` and `SettingsFile` write `.tmp` through it before the rename. `Tools/NewGameArg` (`--new-game`), `Tools/CanvasStretch` (the `--menu` capture's 2D size).
- `scenes/main/Main.tscn` (`scripts/main/Main.cs`, `Roadman.Scenes.Main`) is `run/main_scene`. `--screenshot` or `--perf` in the user args: direct start (`State` `DirectStart`), `World` at once, no menus, settings, pause or quit handling (with `--menu` the UI is built for the screenshot tool, still without settings, input or quit handling; see "Screenshots"). `--new-game`: a new game at once. Else the main menu on a flat background; no map until a game starts. States (`MainState`): `Starting`, `DirectStart`, `MainMenu`, `Loading`, `LoadFailed`, `Playing`, `Paused`. `World` is added with `ProcessMode.Pausable` (Main and its UI are `Always`), so pausing (`GetTree().Paused`) stops all of `World`. While paused (the pause menu and everything over it, and the `--menu` pause, settings and slots captures) `World.Hud` (the street label) is hidden, so it never shows through a menu. `GameStarted` fires once the player is placed; the loading screen ("Loading <display_name>…") shows until then, and a load or spawn failure (`World.StartFailed(message)`) shows the message and "Back to main menu" and frees `World`.
- Input: `World._Input` runs before `Main._Input` (child first). `Main` opens the pause menu on `pause` while `Playing`; in the menus `pause` or `ui_cancel` is `Back()` (cancel a dialog, leave the slot list, resume from the pause menu; nothing on the main menu's top level or while loading). `Resume()` releases the actions pressed this frame and calls `World.OnResumedFromPause()`: the player ignores `jump` and `run_toggle` until a physics frame sees each released (`Player.SuppressPressesUntilReleased()`; a tap shorter than one physics tick is still just-pressed in the next physics frame, which `Input.ActionRelease` outside it doesn't clear), and the death screen ignores dismiss presses for the rest of that process frame. So the closing press doesn't jump or dismiss. `project.godot` overrides `ui_accept` and `ui_cancel` (Godot 4.7's built-ins hold only Enter, Kp Enter, Space and Escape; kept verbatim) to add the south face button (button 0) to `ui_accept` and the east face button (button 1) to `ui_cancel`, device −1, for the menus. In the game no control has the focus once the menus are hidden, and `Main` ignores `ui_cancel` while `Playing`, so the south button only jumps and the east button does nothing. Window focus loss while `Playing` opens the pause menu (while `Loading`: once loading ends). `AutoAcceptQuit` is off outside direct start; `NotificationWMCloseRequest` asks "Quit the game?" (with the autosave line during a game).
- Saves: `Main.Slots` over `FileSaveStore` (`scripts/saves/`, default `user://saves/`). `MakeSave(autosave)`: `Snapshot(includePosition)` + `World.PlayerFacingYaw`, map id, the manifest's `generated_at` (`"unknown"` if absent), `Main.GameVersion` (`application/config/version`, committed `dev`; `release.yml` writes the tag), UTC now, play seconds. Manual saves need `World.CanSave` (state `Alive` and a player). The autosave is written on Quit to menu and on quitting the game, in every death state (outside `Alive`: no position); not while loading. A failed autosave offers "Quit without saving".
- Loading: `World.PendingLoad` (a `SavePlayer`, set before it enters the tree) replaces the first spawn: an empty position spawns normally; else `World.CheckLoadPlacement(x, z, out feet, fromY)` (a downward ray from `World.LoadRayHeadroom` (2 m) above the saved height, so a save under a bridge loads under the deck, hits `map_terrain` or `map_roads` first, the capsule `SpawnDropHeight` above it overlaps only terrain and roads) places the player there facing the saved yaw, else the spawn draw and `Main.Notice` shows `Main.MapChangedNotice`. `World.PlayerLoaded(position, moved)` fires (not `PlayerSpawned`); it prints `Player: loaded at (...)`. A save whose map has no pack is "Map <id> not installed" in the slot list and can't be chosen.
- Settings: `GameState.Settings` from `user://settings.json` (`GameState.LoadSettings()`/`SaveSettings()` over `SettingsFile`, called by `Main` outside direct start; warnings pushed once; the file is never written on load). `Main` applies everything before the menu shows (`SettingsApplier.ApplyAll`): `ApplyDisplay` (window mode and size through `Main.DisplayBackend`, an `IDisplayBackend`: `GodotDisplayBackend` over `DisplayServer`, borderless fullscreen = `WindowMode.Fullscreen`; tests set `RecordingDisplayBackend`; vsync; `Engine.MaxFps`), `ApplyQuality` (the viewport's `Msaa3D`, `ScreenSpaceAA` and `Scaling3DScale` from `QualityPreset.EffectiveRenderScale`, the directional shadow atlas size and soft filter: `SoftHigh` on High, the project setting otherwise) and `ApplyAudio` (the buses in `default_bus_layout.tres`: `Master`; `Music` and `Effects` to `Master`). `Main` sets `World.QualitySettings` (the sun's splits (1 Orthogonal, 2 and 4 PSSM), max distance and shadows; null, as in direct `World` runs, keeps today's sun) and `World.CameraSettings` on every `World` and on each change.
- Settings view (`scripts/ui/SettingsView.cs`, from the Settings buttons of both menus, also while paused): four tab buttons (Display, Audio, Controls, Gameplay; plain buttons, not a `TabContainer`, so `UiFocus` gives explicit focus), a column of controls per tab, Reset to defaults (per tab, confirmed) and Back. Each change applies at once (`Changed(before, after)`); `Close()` writes the file (a failure: `LastSaveError`, a warning and a notice). A window mode, size or render scale change (`DisplayRevert.NeedsConfirm`) asks "Keep these display settings?" with a countdown in real time (also paused); the display controls are disabled meanwhile; Revert, back (Esc, the east face button), the timeout, closing the view or another dialog replacing it restore the three values. The controls tab reads `InputMap` at open (`ControlRows`): keys by `DisplayServer.KeyboardGetLabelFromPhysical`, mouse look as "Mouse", gamepad inputs by `ControlNames`; a "Debug" table only when `DebugBuild.IsDebug`; no `ui_*` actions.
- UI (`scripts/ui/`): `UiTheme` (one code-built theme, placeholder colours in one place; `UiFocus` for explicit, wrapping focus neighbours), `MainMenu`, `PauseMenu`, `SlotList`, `SettingsView`, `ConfirmDialog`, `LoadingScreen`, `NoticeLabel`; the death screen uses it too. Full-rect controls are anchored with `SetAnchorsAndOffsetsPreset` (`SetAnchorsPreset` in `_Ready` leaves a 0×0 rect). Disabled buttons have `FocusMode.None`; the first enabled control gets focus. Godot's default font; gamepad inputs as generic text names.
- User data: `application/config/use_custom_user_dir` with the folder `RoadmanSimulator` (`OS.GetUserDataDir()`). Never write player data into `maps/`.
- Tests: set `Main.UserArgs`, `Main.SavesFolder` (a temp folder), `QuitOnConfirm` false (a quit sets `ExitCode` and emits `QuitRequested`) and `GameState.Instance.SettingsPath` (reset to null) before adding `Main`, and `Main.DisplayBackend` (a `RecordingDisplayBackend`) when the test changes display settings. `MainTestSupport.BeginTest` records the engine state `Main` changes (viewport anti-aliasing and scale, `Engine.MaxFps`, the buses, `GameState.Settings`) and `TearDown` restores it, with the shadow atlas and filter, unpauses the tree and resets `DebugBuild.Override`. Focus loss and close requests: `GetTree().Root.PropagateNotification(...)`.

## Orthophoto debug view

- F2 (`debug_orthophoto`, physical key) switches every loaded tile's terrain between `MapLoader.TerrainMaterial` and an unshaded material with that tile's aerial image (`scripts/debug/OrthophotoDebugView.cs`). Unshaded, because the photo already contains the sun's shading. While it is on, the bottom-right corner shows the attribution and licence of every manifest credit with source `mml_orthophoto` (`MapManifest.Credits`); the text always comes from the manifest.
- Debug builds only: `World` adds the view when `DebugBuild.IsDebug`.
- The images are `res://maps/<id>/debug/orthophoto/<tile_id>.jpg`, about 512x512, written by the pipeline with a `.gdignore` in `debug/`, so Godot never imports or exports them. The view reads them from disk with `Image.LoadFromFile` on the first switch-on (with mipmaps, cached until the map reloads). A tile without an image keeps the placeholder; with no images at all it shows "No orthophoto in this pack; run /regen-map <id>" and stays off.
- Don't add an export filter that includes `maps/*/debug/`: the files are debug-only, and the `.gdignore` is what keeps them out of the import cache and exports.

## Road graph debug view

- G (`debug_road_graph`, physical key; F3 is Mission Control on macOS) toggles a drawing of `MapLoader.RoadGraph` above the surfaces (`scripts/debug/RoadGraphDebugView.cs`): drivable edges coloured by class, walkable-only edges in one colour, arrows on one-way edges, nodes coloured by kind (`span_end` nodes, where a bridge deck meets the road, are magenta triangles), and a legend. Sizes and colours are exports.
- Debug builds only, like the orthophoto view. Without a graph it shows "No road graph in this pack; run /regen-map <id>" and stays off. A map without roads has an empty graph (the pipeline always writes `road_graph.json`); the view then switches on with nothing drawn and a legend saying "road graph is empty".

## HUD street label

- `scripts/hud/StreetLabelHud.cs`, a `CanvasLayer` with one `Label` at the bottom centre, in debug and release builds (`World` always adds it). It shows `StreetLabel.Format` of the road graph edge nearest in 3D to the reference point within `StreetMaxDistance` (export, 40 m), else nothing. Street names, road numbers and road classes only, never business names.
- Reference point: `Target` (export; `World` sets it to the player when it spawns), else the first `map_roads` or `map_terrain` hit of a downward ray from the camera (`Camera`, or the current camera of the viewport the layer is in). No hit: empty. Updated every physics frame; the text and `StreetChanged` signal change only when the text does. `UpdateStreetAt(point)` sets it from a given point (tests).

## Place inspector

- I (`debug_inspect`, physical key) toggles `scripts/debug/PlaceInspector.cs`: a crosshair at the screen centre and a panel on the left. Each physics frame a ray from the camera through the centre is cast. A `map_buildings` body shows its building (id, category and `category_source`, every `category_raw` value, `mml_building` and `mml_overlap`, name fields and `name_source`, each override under the field it set, address, height, its POIs and POI areas); any other hit shows the POI point within `PoiPickRadius` (export, 3 m), else the smallest POI area containing the hit's x/z, else "No building or point of interest here". Without `Places`: "No place data in this pack; run /regen-map <id>". The text comes from `Roadman.Core.Maps.PlaceText`.
- A map load or failed reload clears the selection and the panel text at once; the next physics frame inspects the new map.
- Debug builds only, like the other debug views. The panel shows real business names from the pack; it never ships.
- For tests: `Enabled`, `SetEnabled`/`Toggle`, `InspectRay(from, to)`, `InspectHit(collider, position)`, `InspectCentre()`, `SelectedBuilding`, `SelectedPoi`, `SelectionId`, `PanelText`, `LastRayHit` (whether the last ray hit any collision body), and the `Toggled` and `SelectionChanged` signals.

## Screenshots

`godot --path game --resolution 1600x900 -- --screenshot <preset> <out.png> [--presets <file>] [--map <map-id>] [--orthophoto] [--road-graph] [--inspect] [--player] [--death <fall|screen>] [--menu <main|pause|settings|slots>] [--seed <n>]`, run from the repo root (`/verify` runs it for every preset in the pack, with `--map "$MAP_ID"`, once more for `overview` with `--road-graph`, for `centre-street-level` with `--inspect` and with `--player`, and for `world-edge` with `--death fall` and `--death screen` (`world-edge-death-<v>.png`; N/A without the preset), and for `overview` with each `--menu` value (`menu-<v>.png`)).

- `--menu <main|pause|settings|slots>` renders a menu (spec criterion 24). With `--screenshot` and `--menu`, `Main` builds its UI in the direct start but loads and applies no settings, leaves `AutoAcceptQuit` and handles no input. After the map, debug-data, collision, look-at and ground-relative checks (same exit codes) the tool calls `Main.ShowMenuForScreenshot`: `main` the main menu on its background; `pause` the pause menu over the paused tree (the tool and its capture viewport run `Always`); `settings` the Display tab opened from the pause menu; `settings` uses a fixed usable screen (`Main.ScreenshotUsableScreen`, 2560×1440) and the defaults, so the image doesn't depend on the machine; `slots` the load-mode slot list from the pause menu over a temporary folder (`Main.UseSavesFolder`) with `WriteSampleSaves` (autosave and slot 1 valid, slot 2 damaged), deleted afterwards. Main's UI root is moved into the capture viewport, whose `Size2DOverride` is the project's base 2D size (so the menus lay out as in the game). It prints `Screenshot: --menu <v>`. Exit 1 in a non-debug build or with `--player`, `--inspect`, `--death`, `--orthophoto` or `--road-graph` (argument errors).

- `--road-graph` renders with the road graph debug view on, its legend inside the capture. Exit 1 in a non-debug build or when the pack has no road graph.
- `--inspect` renders with the place inspector on: the capture camera aims the screen centre, and so the inspector's ray, at the preset's look-at point, and the panel and crosshair are moved into the capture viewport. Exit 1 in a non-debug build, when `MapLoader.Places` is null, or when the centre ray hits something other than a building after the settle frames (the image must show the panel on a building, spec criterion 18; aim the preset's look-at at one). A centre ray that hits nothing has left the built area (a test-area pack, for example): exit 2 with `N/A: outside built area` (`PlaceInspector.LastRayHit` is false).
- `--player` renders the player in the third-person view (spec criterion 23). After the look-at and ground-relative checks it waits for the spawned player (up to `World.SpawnPhysicsWaitFrames` + `PlayerSpawnMarginFrames` physics frames), puts it on `MapLoader.GroundOrRoadHitAt` (the highest `map_terrain` or `map_roads` hit) at the preset's look-at x/z, facing away from the preset's camera position, with its input off, shows it, turns its camera behind it (`PlaceBehind`) and sets `StreetLabelHud.Target` to it; once `IsOnFloor()` (within `PlayerFloorWaitFrames`) the capture camera copies the player camera's transform and `Fov` each of the `SettleFrames` frames. It prints `Screenshot: --player at (x, y, z), facing <deg>°`. The player camera never becomes current (the capture camera renders in its own viewport). Exit 1 in a non-debug build, with `--inspect` (an argument error), when the player didn't spawn (the message gives `World.LastSpawnFailure`), with no terrain or road under the look-at point, or when the player isn't on the floor in time; the look-at test (exit 2) applies as for every preset.
- `--death <fall|screen>` renders the death sequence (spec criterion 25). After the look-at and ground-relative checks it waits for the spawned player as `--player` does, sets `World.FallTime` (`fall`) or `World.ScreenTime` (`screen`) to `DeathHoldTime` (3600 s) so the sequence holds in that stage, and `World.MinScreenTime` too, so a key pressed in the window can't dismiss the screen, and puts the player at `EdgeGeometry.NearestRingPoint` of the look-at x/z, `EdgeGeometry.VoidInnerOffset` (the smallest ring distance of a void prism corner; `boundary.json` has no `inner_offset_m`) + `DeathOutwardMargin` (1 m) outward, at `LedgeHeightAt(s)`, facing outward, shown, input off; the world's void test starts the sequence (within `DeathStartWaitFrames`). It prints `Screenshot: --death <v> at (x, y, z)`. `fall` waits for `DeathCamera.IsFinished`; `screen` moves `World.DeathScreen` into the capture viewport and waits for state `DeathScreen` and `Opacity` 1. Then the capture camera copies `DeathCamera`'s transform and `Fov` each settle frame. The death camera is current only in the window's viewport, whose 3D is disabled. Exit 1 in a non-debug build, with `--player` or `--inspect` (argument errors), without a spawned player, without `MapLoader.EdgeGeometry`, or when the stage isn't reached in time.
- The HUD street label is moved into the capture viewport in every screenshot, so it is in the image and measured from the capture camera.

- `--map <map-id>` renders that pack instead of the one in the `roadman/map/id` project setting: the tool sets `MapLoader.MapId` before the map loads. The id must be a lowercase slug (the pipeline's `SLUG_PATTERN`).
- `--orthophoto` renders with the orthophoto debug view on (see "Orthophoto debug view"). Its attribution overlay is moved into the capture `SubViewport`, so it is in the image (a `CanvasLayer` draws only in its own viewport). A pack without orthophoto images, or a build without the view (not a debug build), exits 1.
- Presets come from the rendered pack's `camera_presets.json`, or from `--presets <file>` (handy for trying a preset before it is in the pipeline). The reader follows the pipeline's rules: unknown or repeated keys, an empty `presets`, duplicate or non-slug preset names and `null` for `fov` or `ground_relative` are errors. A relative output or presets path resolves against the shell's working directory (`$PWD`), not `res://`: Godot changes into the project folder for `--path`. Where `PWD` isn't set (Windows `cmd`, PowerShell), pass absolute paths.
- The image comes from its own 1600x900 `SubViewport` (`ScreenshotTool.ImageSize`), so it doesn't depend on the window size, display scaling or window position. `--resolution` only sizes the window.
- Exit codes: 0 saved, 1 error (bad arguments, unknown preset, missing pack or presets file, a map that failed to load or loaded fewer tiles than the manifest lists, `--headless`, flat-colour image, `--orthophoto` without orthophoto images, `--road-graph` or `--inspect` without their data or outside a debug build, `--inspect` with something other than a building at the screen centre, `--player` outside a debug build, with `--inspect`, without a spawned player, without ground under the look-at point or not on the floor in time, `--death` outside a debug build, with `--player` or `--inspect`, without a spawned player or edge geometry, or not reaching its stage, terrain collision not queryable after the physics-frame wait), 2 the whole map loaded but nothing (no terrain, no world-edge cliff) is below the preset's look-at x/z, the ground-relative preset has no terrain under it, or the `--inspect` centre ray hits nothing (prints `N/A: outside built area`, writes no PNG).
- `--headless` disables rendering, so the tool refuses to run under it. For tests, `ScreenshotTool.QuitOnFinish` (export, default true) false keeps the tree running and `ExitCode` holds the code it would have quit with.
- Look-at outside the map (ADR 0008: with a test-area pack, presets outside the area are N/A). The order is: the map loads (every manifest tile, else exit 1), the debug-view data checks (`--orthophoto`, `--road-graph`, `--inspect`, exit 1; a build without the view, or `--player` outside a debug build, already exits 1 when the tool is added, before the `--headless` refusal and the map load), the terrain-collision wait (`MapLoader.WaitForTerrainCollisionAsync()`, because new bodies are queryable only after a physics frame; a timeout is exit 1 for every preset, ground-relative or absolute, because the map or its collision didn't load; never N/A), then the look-at test, then the ground-relative camera test. The look-at test casts a downward ray at the preset's look-at x/z, as `TerrainHeightAt` does, with `MapLoader.GroundOrEdgeHitAt`: a hit on the terrain (`map_terrain`) or on the world-edge cliff (`map_edge`) means inside (`PresetPlacement.CheckLookAt`); no hit exits 2 with `N/A: outside built area (preset '<name>' looks at x <x>, z <z>: a downward ray there hits neither the terrain (map_terrain) nor the world-edge cliff (map_edge))`. So notches in the boundary, tiles the pipeline didn't write, and the void past the boundary (for example over Kirkkojärvi past B's west notch) are N/A, while the cliff ledge isn't. Only x and z of the look-at count, for absolute and ground-relative presets alike; the camera position may be over nothing (`world-edge` is). The ground-relative test then needs terrain under the camera (`N/A: outside built area (preset '<name>' has no terrain under its camera at x <x>, z <z>)`). With `--player`, the spawned-player wait, the ground-or-road hit at the look-at and the on-floor wait come after it (each exit 1). Numbers in these messages and the `Screenshot: preset ... camera at ...` line are culture-invariant (`0.###`).
- The flat-colour check catches an empty or cleared image, not a camera below the terrain: the terrain is one-sided, so from below it is invisible and the image shows the underside of the buildings.

**macOS.** Godot has no off-screen display driver on macOS. The run opens a normal window (Metal) for about 3 s, and needs a logged-in GUI session. `--position` can't hide it: macOS moves the window back on screen (tried `-5000,-5000` and `20000,20000`). The saved image was byte-identical for every window position and for a 200x100 window. Don't minimise the window while it runs.

**CI (Linux).** CI doesn't run screenshots (ADR 0010). The route to try is to run under a virtual X server, with Mesa's lavapipe software Vulkan driver so Forward+ renders without a GPU: `xvfb-run -a godot --path game --resolution 1600x900 -- --screenshot ...` with `xvfb` and `mesa-vulkan-drivers` installed on the runner. If Vulkan isn't available, add `--rendering-driver opengl3` (Compatibility renderer); its images look different from Forward+, so don't compare them with macOS ones. These are runner packages, not project dependencies. Untested so far.

## Export

`game/export_presets.cfg` has two presets with no credentials: "Windows Desktop" (x86_64, PCK embedded) and "macOS" (universal, ad-hoc signed). Both exclude `addons/gdUnit4/*`, `tests/*` and `gdunit4_testadapter_v*/*` (ADR 0010). Export needs the .NET export templates; `.claude/scripts/check-export.sh <build-dir>` checks a build folder that also holds `NOTICE.txt` (`mapgen notice`), `CREDITS.md` and `licenses/` (`python3 -I .claude/scripts/collect-licenses.py <build-dir>`).

```sh
godot --headless --path game --export-release "Windows Desktop" "$PWD/build/export/windows/RoadmanSimulator.exe"
godot --headless --path game --export-release "macOS" "$PWD/build/export/RoadmanSimulator-macos.zip"
```
